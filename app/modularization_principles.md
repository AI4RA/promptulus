### Modularization Principles

Split for checkpoints, handoffs, and repeat failures, not because the model cannot think in steps. One prompt may be enough.

| Advice Category | Principle | Why This Works | What It Is | Limitations |
| :--- | :--- | :--- | :--- | :--- |
| **Level 1: Framing the Task** | **Try One Prompt First** | As of October 2026, OpenAI's and Anthropic's guidance is to start simple: current models handle most multistep reasoning in one pass. | State the whole task in one well-scoped prompt. Split only where you must check the work before the next part, where it changes hands, or where a step keeps failing. | A single pass hides intermediate reasoning, so a budget you will sign may still want a checkpoint. If the goal is fuzzy, see Telosa first. |
| **Level 1: Framing the Task** | **Identify Distinct Cognitive Actions** | Every "and" or "then" is a candidate break. Cut only where you need to see the output before it feeds the next step. | "Pull the salary figures, check them against the justification, flag mismatches" has a checkpoint after the pull: verify the numbers first. | Over-splitting costs shrimp: each extra step is a handoff where context and your time are lost. |
| **Level 1: Framing the Task** | **Sequence from Abstraction to Detail** | Structure is cheaper to change before detail is written. | Ask for structure first ("Outline the Facilities and Resources section, headings only"), approve it, then ask for content under each heading. | A vague outline step gives the detail steps nothing to hold onto. |
| **Level 2: Chaining Logic** | **Define Inputs and Outputs Explicitly** | Each step gets a contract: what it receives, what it produces, who uses it next. | One line per step: "Input: the subaward agreement. Output: a table of flow-down clauses with page numbers. Used by: the compliance comparison step." | Overkill for a one-off; write it down when you will repeat or share the workflow. |
| **Level 2: Chaining Logic** | **Use Stable Intermediate Artifacts** | A saved table or list is a checkpoint you can inspect, correct, and restart from; Anthropic's prompt-chaining guidance calls these gates (as of October 2026). | Save each step's output as its own document (extracted figures, clause table), correct it there, then paste the corrected version into the next step. | More files to track; name them by step ("01_extracted_figures"). |
| **Level 2: Chaining Logic** | **Carry Forward Only Essential Context** | Attention quality, not token budget: Anthropic's context engineering guidance (as of October 2026) notes that as a context fills, the model's ability to use what is in it degrades. | Fresh conversation per module, pasted material first, instructions last. Ask each step for a structured output - a table or labeled fields - so the next handoff is clean and easy to check. | Over-compressing drops nuance; carry exact figures or clause text when precision counts. Mnemos covers what to include. |
| **Level 3: Execution Strategy** | **Draft, Review, Refine** | Self-correction is the most common useful chain: draft, review against explicit criteria, revise. Anthropic calls this evaluator-optimizer (as of October 2026). | 1: "Draft the personnel budget justification from these figures." 2, fresh conversation: "Review against the NSF PAPPG; list problems, do not rewrite." 3: "Revise to address these." You check the list before step 3. | A model reviewing its own work can be lenient; give it concrete criteria. Judging final output is Veridex's domain. |
| **Level 3: Execution Strategy** | **Ask the AI to Propose the Steps** | Planning without solving lets you approve the plan where it is cheapest to change. | "List the steps you would take to assemble this RPPR from the attached materials. Do not start on any of them." Edit the list, mark your checkpoints, then run the steps one at a time. | Proposed steps may be too granular; merge any with no check between them. Tell it your institution's approval points. |
| **Level 3: Execution Strategy** | **Label Each Prompt by Function** | A visible label keeps each step's job clear and makes a saved chain readable later. | Prefix each prompt with its role: `[EXTRACT]`, `[DRAFT]`, `[REVIEW]`, `[REVISE]`. | Labels do not change behavior by themselves; the instructions under them do the work. |
| **Level 3: Execution Strategy** | **Test the Smallest Viable Chain First** | A short chain run end to end on one real case shows whether the handoffs work. | Run extract, check, compare on one subaward before building the full compliance workflow. | Test a messy case too, not just a clean one. |
| **Level 4: Review & Optimization** | **Iterate by Swapping One Module at a Time** | Changing one step and re-running tells you what that change did; changing three at once does not. | Rewrite only the `[REVIEW]` prompt, re-run on the same input, compare. | Slow for long chains; keep them short. |
| **Level 4: Review & Optimization** | **Reuse the Pattern** | Once a decomposition works it is a template: the thinking is done and the next run is paste-and-fill for you or a colleague. | Save the step prompts in order, with labels and checkpoints, as a text file ("Subaward compliance check - 3 steps"). Reuse and adapt it. Clarion covers documenting a given run. | A template built for one sponsor may miss another's rules; re-read the steps when the task changes. |

#### Two worked examples

**NSF budget justification review (three steps, two checkpoints).** `[EXTRACT]` "Return a table: line item, budget figure, figure in the justification, match yes/no." Checkpoint: confirm against the spreadsheet. `[REVIEW]`, fresh conversation, corrected table pasted first: "Against the attached PAPPG budget section, list each item that is unallowable, unexplained, or inconsistent. Do not rewrite." Checkpoint: decide which findings are real. `[DRAFT]` "Write the email to the PI listing these findings." The split exists so you check the numbers and findings before the PI sees them.

**NOFO eligibility read (one prompt is enough).** "Here is the NOFO and our institution profile. List every eligibility requirement, mark each met, not met, or unclear, and quote the NOFO language." No step needs a check before the next, so splitting would add handoffs without adding a checkpoint.
